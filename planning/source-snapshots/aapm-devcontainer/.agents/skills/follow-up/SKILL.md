# Contextual Follow-up Skill

Use this skill to evaluate project progress and determine next actions across either the entire workspace (Root Main Chat) or a specific project subfolder.

## Scope & Path Resolution (Context-Based Follow-up):
- **Step 1: Determine Chat Purpose:** Always ask yourself: "What is the purpose of this chat? Is it a general chat or is it specialised?"
- **Step 2: Choose & Limit Directory:** 
  - If **Specialised**, choose the exact specific leaf directory related to the active context (e.g., `Jobs/TA_Positions/Replies/Nina_Sostaric_NB2410_NB1420/` or `Academics/BEP/Catalysis/`). 
  - **CRITICAL:** Limit the scan *strictly* and *exclusively* to that specific directory. Do NOT broaden the scope to a parent directory (e.g. `Jobs/TA_Positions/`) or dump unrelated sibling folders.
- **Global / Master Scan:** Only if the chat purpose is strictly **General** (e.g. a fresh startup session without domain context) or the user explicitly asks for `/follow-up all`, scan the entire root workspace.
- **Explicit Scoped Chat / Path Argument:** When invoked with one or more directory arguments or course/topic names (e.g. `/follow-up NB2410 TW3730TU`), identify all corresponding project folders and restrict scanning strictly to `state.md` files within those target trees.

### 2. Recursive State Scanning & Meta Directive Parsing (Write to File)
- **CRITICAL:** Run the scan script and **write all results to a temp file** (e.g. `.agents/triage/follow_up_scan.txt`), then read it back with `view_file` in chunks.
- **Multi-Path & Multi-Course Input:** Always pass all target directory paths as arguments to the script (`pixi run python .agents/triage/scan.py path1 path2 ...`). If the user specifies multiple courses/projects, resolve each directory and scan each target folder, consolidating all outputs into `.agents/triage/follow_up_scan.txt`.
- **Honor Meta & Snooze Directives:**
  - `<!-- SNOOZE: until YYYY-MM-DD / condition -->`: If the current date is before the snooze date, or condition is not met, collect the item but place it at the very bottom of the scan report under a "⏳ Snoozed / On Hold" section so it is not completely hidden but doesn't clutter active actions.
  - `<!-- META: ... -->` (e.g. Nina 28.10 quiz resit): Strictly adhere to the stated reporting constraint (e.g. do not surface until 1-2 weeks prior).
- **Recommended scan script pattern (multi-path enabled):**
  ```python
  import os, re, sys
  from datetime import datetime

  # Accept one or more target directories from CLI arguments, default to '.' for global scan
  target_dirs = sys.argv[1:] if len(sys.argv) > 1 else ['.']
  results = []
  snoozed_results = []
  open_lines = []
  skip = {'.git', '.agents', '.gemini', 'node_modules', 'dist', 'build', 'browser_context', 'archive', '0_Project_Management'}

  for target_dir in target_dirs:
      target_dir = target_dir.strip().rstrip('/\\')
      if not os.path.exists(target_dir):
          continue
      for root, dirs, files in os.walk(target_dir):
          dirs[:] = [d for d in dirs if d not in skip]
          for file in files:
              if file != 'state.md':
                  continue
              filepath = os.path.join(root, file)
              relpath = os.path.relpath(filepath, '.')
              with open(filepath, 'r', encoding='utf-8', errors='ignore') as f:
                  content = f.read()
              
              # Check snooze directives
              snooze_match = re.search(r'<!--\s*SNOOZE:\s*until\s*(\d{4}-\d{2}-\d{2})', content)
              is_snoozed = False
              snooze_date_str = ""
              if snooze_match:
                  try:
                      snooze_date_str = snooze_match.group(1)
                      snooze_date = datetime.strptime(snooze_date_str, '%Y-%m-%d').date()
                      if datetime.now().date() < snooze_date:
                          is_snoozed = True
                  except ValueError:
                      pass
              
              checkbox_matches = re.findall(r'^[ \t]*- \[([ xX/])\] (.*)', content, flags=re.MULTILINE)
              unchecked_tasks = [body for marker, body in checkbox_matches if marker.lower() != 'x']
              # Also queue all checked entries, with file:line provenance, in a
              # distinct CHECKED ITEMS FOR EVIDENCE REVIEW section (see actual scan.py).
              
              status = re.search(r'- \*\*Status.*?:\*\*(.*)', content)
              if not status:
                  status = re.search(r'\| \*\*Status\*\* \|(.*)\|', content)
                  
              # Parse Open Communication Lines table if present
              table_match = re.search(r'## ⏳ Open Communication Lines.*?\n\n\|.*?\|.*?\n\|[-| ]+\|\n(.*?\n)(?:\n|##|---|\Z)', content, flags=re.DOTALL)
              lines_found = []
              if table_match:
                  rows = table_match.group(1).strip().split('\n')
                  for r in rows:
                      if '|' in r and not r.startswith('|---') and not 'No pending' in r and not r.strip() == '':
                          parts = [p.strip() for p in r.strip().strip('|').split('|')]
                          if len(parts) >= 4 and parts[0] != '':
                              lines_found.append((relpath, parts[0], parts[1], parts[2], parts[3]))

              status_text = status.group(1).strip() if status else "No explicit status"
              
              block = [f"\n=== {relpath} ==="]
              block.append(f"  Status: {status_text}")
              if is_snoozed:
                  block.append(f"  [SNOOZED until {snooze_date_str}]")
              for t in unchecked_tasks:
                  block.append(f"    - [ ] {t.strip()}")
                  
              if is_snoozed:
                  snoozed_results.extend(block)
              elif unchecked_tasks or lines_found or "ACTIVE" in status_text or "WAKE UP" in status_text:
                  results.extend(block)
                  
              for lf in lines_found:
                  open_lines.append(lf)

  out_dir = os.path.join('.', '.agents', 'triage')
  os.makedirs(out_dir, exist_ok=True)
  out_path = os.path.join(out_dir, 'follow_up_scan.txt')
  with open(out_path, 'w', encoding='utf-8') as out:
      out.write("=== 🔥 ACTIVE PROJECTS & DIRECT ACTIONS ===\n")
      out.write('\n'.join(results))
      out.write("\n\n=== ⏳ OPEN COMMUNICATION LINES ===\n")
      for fp, c, s, d, o in open_lines:
          out.write(f"  [{fp}] {c} | {s} | {d} | {o}\n")
      if snoozed_results:
          out.write("\n\n=== 💤 SNOOZED / ON HOLD ===\n")
          out.write('\n'.join(snoozed_results))
  ```

4. **If unverified or contradictory, do not launder it.** Do not silently prune it or report it as done; keep an explicit **UNVERIFIED/CONFLICT** reconciliation record and refer to the precise source requiring verification. ### 5. Categorized Action Summary & Output Structure (Classic Format)

The `/follow-up` report MUST follow the established classic 4-part structure.

#### 0. 🚨 HARD-EXTERNAL-DEADLINE BANNER (rendered ABOVE everything)

**This block outranks every other section, including the timeline tables.**

Before section 1, emit a `# 1` header (a true top-level header, not a table row) for any item that is:

- an **external, hard, same-day or already-past deadline the user can still act on** (registrations, sign-ups, submissions, replies that close today), **or**
- a **load-bearing decision** that blocks a multi-week path and is due within 48 h.

**Rule 38 gate — verify the anchor type BEFORE escalating.** Eligibility above requires an *evidenced external cutoff*. A date is not a deadline merely because it is the only date on the page. Consult the taxonomy in `.agents/AGENTS.md` §5.11 first:
- `[DEADLINE:]` — a source states a cutoff → header-1 eligible, including when past but still mitigable.
- `[EVENT:]` — the thing merely happens and joining on the day is still possible → **never** the hard-deadline banner. It stays a normal item in section 1, and the register/prepare action is `[LEAD:]` relative to it.
- `[DATE?: …] UNVERIFIED` — cutoff unconfirmed → do not escalate. Report the uncertainty and ask the user or the organiser.
- "already past" splits two ways: **past deadline with live mitigation** (still reportable, header-1 eligible) vs **past event, nothing left to do** (close the loop in `state.md`, report as closed, never as a breach).

Format:

```
# 1. <SHORT TITLE> — <ABSOLUTE DATE> — <PRIO 1|2|3>
<one line: what it is, why it is top of the report>
- [ ] **[QUICK-WIN <N MIN> | DUE: YYYY-MM-DD]** <atomic action> ([`thread_x.md`](...))
```

Rules:
- A **verified `[DEADLINE:]`** the user can still meet on the day it is scanned MUST be header `# 1`, never a row buried in a timeline table. The user's own correction: *"Dit soort dingen moeten gewoon header 1 worden in follow up."* Being joinable on the day is **not** what qualifies an item — see the Rule 38 gate above.
- Max 3 such header-1 blocks per report. If more qualify, rank by irreversibility (an external registration you cannot redo > an internal task you can always defer).
- State the deadline in **absolute** form and say whether it is still open or breached-with-mitigation. Never bury a breach. Never manufacture one: an `[EVENT:]` whose date has passed is closed, not breached.
